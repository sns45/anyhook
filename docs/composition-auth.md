# Auth composition: anyhook does not build authentication

anyhook is an outbound webhook **delivery engine**. It deliberately ships **no authentication system** (requirements §10, G8). Authenticating the producer's end customers is a separate concern owned by the sibling project **auth-gateway** (or any auth layer the producer already runs). This document shows how to compose the two.

## The boundary

Every portal and ingest route resolves a **tenant** — the isolation scope for endpoints, deliveries, secrets, and rate limits (G7). anyhook never derives the tenant from a request body. It reads a single trusted signal that your auth layer sets:

```
x-anyhook-tenant: <tenant-id>
```

The `createPortalRouter` in `@anyhook/core` (and the deployable Cloudflare Worker that uses it) treats this header as authoritative. A request that reaches anyhook **without** that header is rejected with `401`. A request can never name an arbitrary tenant through the body.

```
                 ┌──────────────────────────┐        x-anyhook-tenant: acme
   client ─────▶ │  your auth (auth-gateway) │ ──────────────────────────────▶  anyhook portal router
   (bearer/JWT)  │  authenticates + maps to  │        (header set by auth,        (trusts the header,
                 │  a tenant, sets header    │         verified upstream)          scopes everything)
                 └──────────────────────────┘
```

**You MUST place an auth layer in front of anyhook** and ensure it:

1. Authenticates the caller (API key, session, JWT, mTLS — your choice).
2. Maps the authenticated principal to a tenant id.
3. **Sets `x-anyhook-tenant`** on the upstream request, and **strips any client-supplied `x-anyhook-tenant`** so a caller cannot forge it.

If anyhook is reachable without that layer, any caller can act as any tenant. Do not expose the Worker publicly without it.

## Wiring it

### Custom resolver

`createPortalRouter(engine, { resolveTenant })` lets you plug any trusted signal (a verified JWT claim, a mTLS subject, a session lookup) instead of the default header:

```ts
import { WebhookEngine, createPortalRouter } from '@anyhook/core';

const handle = createPortalRouter(engine, {
  resolveTenant: (req) => verifyJwt(req.headers.get('authorization'))?.tenantId,
});
```

If your auth layer already runs in the same Worker/process, do the verification there and return the tenant. If it runs as a separate gateway (recommended), keep the default header resolver and let the gateway set the header.

### Cloudflare (auth-gateway in front)

Deploy auth-gateway (or your gateway) as the public entrypoint; route authenticated traffic to the anyhook Worker with `x-anyhook-tenant` set. The anyhook `wrangler.toml` binds only the Durable Objects and the delivery Queue — no auth, no database.

## What anyhook still owns

anyhook owns everything **downstream** of the tenant boundary: signing (Standard Webhooks), fan-out, retry/backoff, circuit breaking, DLQ, the delivery log, and replay. It owns **endpoint signing secrets** (`whsec_`-prefixed), which are generated by anyhook, returned exactly once on create/rotate, and **never** exposed by any read route (the portal redacts `secrets` from every endpoint response, G10).

It does **not** own: who the caller is, how they prove it, or how a principal maps to a tenant. That is auth-gateway's job.
