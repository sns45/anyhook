# anyhook v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build anyhook, an edge-native outbound webhook delivery engine: a producer emits a business event once; anyhook signs it (Standard Webhooks), fans it out to every subscribed customer endpoint, retries transient failures with jittered backoff, circuit-breaks dead endpoints, dead-letters exhausted deliveries, and exposes a delivery log + replay surface. Built on `anyq` for transport; deployable to Cloudflare Workers (Durable Objects) and AWS Lambda (SQS + DynamoDB).

**Architecture:** A runtime-agnostic engine (`@anyhook/core`) defines ports (Transport, StateStore, Scheduler, HttpClient, UrlPolicy, Clock, Rng) and owns the entire webhook-specific state machine (fan-out, retry schedule, circuit breaker, DLQ, delivery log, portal handlers). Adapter packages implement the ports for a runtime (`@anyhook/cloudflare`, `@anyhook/aws`) by composing an anyq transport + a durable state store. `@anyhook/testing` provides in-memory implementations + a scriptable `MockReceiver`. This mirrors anyq's dependency-inversion (core has zero runtime-SDK deps; adapters carry SDKs and depend on `@anyq/core`-style siblings).

**Tech Stack:** TypeScript (ESM, `"type": "module"`, `.js` relative-import extensions, `verbatimModuleSyntax`), **Bun** (`bun build` + `tsc --emitDeclarationOnly` for builds, `bun test` for tests), Bun workspaces monorepo. Cloudflare Workers + Durable Objects + Alarms. AWS Lambda + SQS + DynamoDB. Go 1.25.x port (last path element `anyhook`). Standard Webhooks wire format (HMAC-SHA256).

## Global Constraints

Copied verbatim from `requirements.md`. **Every task's requirements implicitly include this section.**

- **G1 — `@anyhook/core` has ZERO runtime-SDK dependencies** (req §5, §6, hard-req #3). No Cloudflare/AWS/anyq-adapter SDK import may appear in core. Core defines ports; adapters implement them. Enforce with a CI dep-check (see Task M1.0b / proposed decision A3).
- **G2 — Two-layer retry separation** (req §4, hard-req #1). anyq's transport-level redelivery is distinct from anyhook's endpoint-level retry/circuit/backoff state machine. Endpoint retry state lives in the durable StateStore, NEVER inside anyq. Do not put endpoint retry counts into anyq.
- **G3 — Message-level isolation** (req §3 "Key invariant", §8, hard-req #2). The unit of retry/circuit state is the **message** (event × endpoint), never the event. A dead endpoint must provably never delay or fail delivery to a healthy endpoint for the same event. Required test, written early (Task M1.10).
- **G4 — Standard Webhooks wire compatibility** (req §2, §12, hard-req #4). Signing MUST verify with the official `standardwebhooks` npm package and vice-versa. Signed content = `` `${webhook-id}.${timestampSeconds}.${rawPayloadString}` ``; key = base64-decode(secret after stripping `whsec_`); signature = `v1,` + base64(HMAC-SHA256(key, signedContent)); multi-sig space-separated; headers `webhook-id`, `webhook-timestamp` (unix **seconds**), `webhook-signature`; ±5min verify tolerance. Required cross-library test (Task M1.4).
- **G5 — Async `send()`** (req §7.1, §8, hard-req #5). `send()` returns only at durable acceptance (enqueued via transport + idempotency recorded); it MUST NOT block on delivery. Target p99 < ~50ms on Workers.
- **G6 — SSRF protection on by default** (req §10, hard-req #6). Before delivering, block private/loopback/link-local IP ranges, `file://`/non-http(s) schemes, and (configurably) redirects (3xx = failure, do not follow). Safe default deny-list ships ON. Required test (Task M1.9).
- **G7 — Tenant isolation** (req §10, hard-req #7). Every key/query/limit is tenant-scoped. Required no-leak test (Task M1.11).
- **G8 — anyhook does not build auth** (req §10, hard-req #8). Portal APIs mount behind the producer's own auth (auth-gateway's job). Document the composition; do not add an auth system.
- **G9 — Delivery success semantics** (req §8): 2xx = delivered; 3xx = failure (no redirect follow); 4xx except 429 = permanent failure → DLQ, no retry; 429 + 5xx + network/timeout = retryable. Per-attempt HTTP timeout default 15s (configurable); timeout = retryable.
- **G10 — Secrets** (req §10): endpoint signing secrets are `whsec_`-prefixed, base64, ≥24 bytes entropy, generated by anyhook, shown once, never logged.
- **G11 — Payload size cap** default 256KB, configurable (req §10).
- **G12 — Backoff schedule** default `~5s, 30s, 2m, 10m, 30m, 1h, 3h, 6h` (8 attempts, ~12h) then DLQ; **full jitter** over `[0, base_delay]`; respect capped `Retry-After` on 429/503 (req §9.1).
- **G13 — Circuit breaker** per endpoint: `closed → open → half-open`; open after **5 consecutive failed messages** (proposed D4); `open` parks new messages as `blocked` (not attempts); after cooldown → `half-open` single probe; success → `closed` + drain parked; failure → `open` + reset cooldown (req §9.2).
- **G14 — anyhook composes anyq, never reimplements queue logic** (req §5). Transport axis = anyq.
- **G15 — Repo/toolchain conventions (mirror anyq exactly):** `"type": "module"`; build = `bun build ./src/index.ts --outdir ./dist --target bun && bun run build:types` where `build:types = tsc --emitDeclarationOnly --outDir dist`; test = `bun test`; typecheck = `tsc --noEmit`; root `tsconfig.json` strict + `moduleResolution: bundler` + `verbatimModuleSyntax` + `noEmit: true`, package tsconfig extends it flipping `noEmit:false` + `outDir`/`rootDir`; all relative imports use `.js` extension; `import type` for type-only imports; core sub-path-exports its submodules, adapters export a single `.`; adapters list core in BOTH `dependencies` (`workspace:*`) and `peerDependencies` (`workspace:*`); every source file opens with a `/** @fileoverview … @module @anyhook/… */` header; `publishConfig.access: public`, MIT, `author: "Shantanu Sharma"`.

## Open Decisions — MUST be confirmed before implementation (see confirmation request below the plan)

The plan below assumes the **proposed defaults**. Tasks whose shape depends on a decision are annotated `[assumes Dn=…]`. Decisions D1–D7 are from requirements §14; A1–A5 are additional ambiguities this plan surfaces.

- **D1** TS first through M3, Go parity at M4 *(assumed)*.
- **D2** AWS scheduler = **900s split, no delay-chaining** (ADR 0001): ≤900s via native SQS `DelaySeconds`; >900s via a `due_at` GSI + a 60s cron sweeper that claims rows by conditional write before enqueue; DynamoDB TTL is GC-only (never the schedule trigger). Governed by principle **P2 "the state store is the schedule."** *(confirmed)*.
- **D3** One Durable Object per endpoint on Cloudflare *(assumed)*.
- **D4** Circuit trips on 5 consecutive failed messages *(assumed)*.
- **D5** Go reaches M1 + M2 depth (core + one runtime); portal/replay Go parity may trail *(assumed)*.
- **D6** API-only for v0.1, no portal UI *(assumed)*.
- **D7** Monorepo (Bun workspaces) for TS; Go module in same repo under `/go` *(assumed)*.
- **A1** (new) The `adapter: () => import('@anyhook/cloudflare')` one-liner in req §6 is NOT how anyq loads adapters (anyq = separate package + `createX` factory, no dynamic-import registry). **Proposal:** honor the literal API — `WebhookEngine` accepts an `adapter` that is either an adapter module or a `() => import()` thunk resolving to one; the module exposes `createAdapter(config): { transport, state, scheduler, httpClient }`. Keeps anyq's dependency-inversion spirit + the documented one-liner.
- **A2** (new) Golden-file `-update` flag (exec-prompt testing bar) does NOT exist anywhere in anyq. **Proposal:** add it as deliberate net-new for anyhook's Go signing/wire-format tests (M4). TS side uses `bun test` inline snapshots.
- **A3** (new) anyq has no dep-check enforcing core's SDK-freedom (relies on empty `dependencies`). Exec-prompt hard-req #3 says enforce. **Proposal:** add a `bun test` assertion (Task M1.0b) that `@anyhook/core`'s `package.json` has empty runtime `dependencies` + a source grep asserting no `@anyhook/cloudflare|@anyhook/aws|@anyq/*|cloudflare:|@aws-sdk` import appears under `packages/core/src`. Wire into CI.
- **A4** (new) anyq ships libraries, not binaries; has no goreleaser. Exec-prompt says "goreleaser conventions if/when releasing binaries." **Proposal:** no goreleaser for v0.1 (library; tag + module-proxy publish like anyq); revisit only if a CLI binary is added.
- **A5** (**resolved** — ADR 0001; blocks M2/M4, not M1) req §5/§6 assumed `@anyq/cloudflare` and `@anyq/aws`; **neither exists.** Resolution: `@anyhook/aws` composes existing **`@anyq/sqs`**; a new **`@anyq/cloudflare-queues`** driver (technology-named per principle **P1**, **transport only** — Queues producer + push-consumer binding; Durable Objects stay in anyhook's state layer, never in anyq) is added to the anyq repo as a **parallel task gating only M2** (Task M2.0). anyhook M1 proceeds now. requirements §5/§6 amended accordingly.

/** @fileoverview Signing secret generation/parsing. @module @anyhook/signing */
const PREFIX = 'whsec_';
export function generateSecret(bytes = 24): string {
  const buf = new Uint8Array(bytes);
  crypto.getRandomValues(buf);
  return PREFIX + Buffer.from(buf).toString('base64');
}
export function parseSecret(secret: string): Uint8Array {
  const b64 = secret.startsWith(PREFIX) ? secret.slice(PREFIX.length) : secret;
  return new Uint8Array(Buffer.from(b64, 'base64'));
